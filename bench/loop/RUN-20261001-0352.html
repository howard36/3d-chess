Should the client refuse illegal moves from the opponent?

The replay applies any move the server relays, and the server checks only turn order, so an opponent with devtools can move your pieces or jump across the board. README's "Non-goals" says that is accepted ("the threat model is 'my friends'"), so I built the check, measured it and left it out. With a new allocation-free Board.isLegalMove, exhaustively cross-checked against the naive rules, a 3,000-ply replay was within noise (−3%). It adds +48 engine lines and an exhaustive test. The patch is in bench/loop/patches/replay-legality.patch.

Recommendation Adopt it if the game will ever be shared beyond friends; it costs nothing a player would see. Otherwise leave it parked.

Seats can be taken with the link alone

A rejoin needs only the game id and a colour, so anyone with the invitation link can take a seat and evict its player (who then stops reconnecting). Related, from the same reviewer: gameId has no pattern, a socket has no rate limit, and a game has no ply cap. Each is a protocol change (server/schema.json).

Recommendation Decide whether the threat model still holds. If not, a seat token issued at create/join is the first fix, with a migration window for stored seats.

Changed

The piece set preloads on Safari and iOS too (637677f)

The idle preload returned early where requestIdleCallback is missing: every iOS browser and Safari without a flag (MDN browser-compat-data 8.1.3). There the whole set was built and baked inside the first frame that drew pieces. Now each piece is built and baked in its own task, on an idle callback or a 50 ms timer. preloadPieceSet is gone; the baked set's preload already did its work. The bench gained BENCH_NO_IDLE_CALLBACK=1 to time Safari's path.

Quiet marks shade fewer pixels (00db00a)

Every destination of a held piece drew on a quad sized for the soft pool that only a mark straight above or below the piece becomes: 1.03 units square instead of 0.70, about 2.1× the fragments, each running the marks' whole shader in software. The quad is now the ring's size unless the mark is soft. What it draws is unchanged.

The game ships only its own piece set; one scheduler (d74b5c3, bb9840d)

The knight sculptor (knight.ts on sdf.ts and decimate.ts) shipped in the scene chunk though the game only draws the medium set, whose knight ships precomputed. pieceSet() is now that set alone, and pieces/sculpted.ts serves the gallery, benches and tests. The build also carried two extra copies of scheduler under r3f; resolve.dedupe leaves one. Geometry is byte-identical (golden hashes unchanged).

Rules that now run as checks (3c01202, 4a167f4, 7d59f20)

  • The build fails if three.js or r3f reaches the entry chunk; adding import { Vector3 } from 'three' to main.tsx fails it.
  • Two tests mount the real garden: its signature holds still at rest, and every garden material is one the signature can see into. A uniform nudged by 1e-9 a frame fails them.
  • e2e/programs.spec.ts: a whole game (a selection, a capture, check, mate) links no shader program after the warm-up. It counts linkProgram calls. It runs in full motion because under reduced motion its mutation passed.
  • The browser bench records each frame's garden mode (from the copy, taking it, or in full), and the loop's primary.mjs fails on a missing primary row instead of averaging fewer.
